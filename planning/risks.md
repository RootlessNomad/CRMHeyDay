# Risk Register

## Format

| ID  | Risk | Likelihood | Impact | Mitigation |
| --- | ---- | ---------- | ------ | ---------- |

## Risks

| ID   | Risk                                                                   | Likelihood | Impact   | Mitigation                                                                                                                                                                                                                                                  |
| ---- | ---------------------------------------------------------------------- | ---------- | -------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| R-01 | Scraping rompe por cambios en webs objetivo o bloqueos anti-bot        | High       | Med      | Playwright con user-agent real, timeouts generosos, fallback por fuente, log de errores visible en admin, reintentos con backoff. No saltar anti-bot, fallar limpio.                                                                                        |
| R-02 | Coste de Claude descontrolado (contenidos largos, reintentos)          | Med        | High     | Prompt caching obligatorio; selección de modelo por tarea (Haiku para extracción, Sonnet para redacción, Opus solo bajo flag); límite duro diario configurable en admin; dashboard de coste; truncado de inputs.                                            |
| R-03 | Pain points alucinados por el LLM perjudican credibilidad del outbound | High       | High     | Prompts que exigen evidencia textual; categorización forzada en 3 niveles; separación estricta entre `observed` (con cita literal) y `speculative`; UI que muestra la evidencia junto al pain point; revisión humana obligatoria antes de usar en outbound. |
| R-04 | Credenciales de terceros filtradas o comprometidas                     | Low        | Critical | Cifrado AES-256-GCM con clave maestra en env (Level 2); nunca se devuelven en claro vía API; rotación soportada; audit log de accesos; no aparecen en logs ni en respuestas de error.                                                                       |
| R-05 | Regresión por desviar scope a features que "parecen útiles"            | High       | Med      | Regla de CLAUDE.md #6 aplicada estrictamente; cualquier feature fuera de la lista de UJ requiere aprobación explícita; `/review` tras cada milestone.                                                                                                       |
| R-06 | Enriquecimiento bloquea la UI o timeout del request                    | Med        | High     | Todo enriquecimiento es asíncrono (BullMQ + Redis); frontend consulta estado del job por polling / SSE; UI muestra estado `queued` / `running` / `done` / `failed` con error legible.                                                                       |
| R-07 | Datos GDPR-sensibles mezclados con datos públicos                      | Med        | High     | Esquema de datos separa campos públicos (empresa) de campos personales (contacto); derecho al olvido implementado en contactos; logs de acceso; no se persisten páginas HTML completas, solo extractos normalizados + URL + timestamp.                      |
| R-08 | Contenido generado suena a "AI buzzword soup" o rompe tono HeyDay      | High       | Med      | System prompt con guía de voz detallada + ejemplos positivos/negativos; validador post-generación que marca palabras prohibidas; revisión humana obligatoria antes de `approved`.                                                                           |
| R-09 | Planning desborda (muchas UJ, proyecto se vuelve inmanejable)          | Med        | High     | Milestones de 4-6 UJs; `/review` tras cada milestone; scope fijo de v1; diferimientos documentados.                                                                                                                                                         |
| R-10 | Base de datos sin backups antes de producción                          | Low        | Critical | Plan de backups diarios via `pg_dump` en deployment script; restore testado antes de delivery.                                                                                                                                                              |
| R-11 | El modelo Anthropic cambia o el ID se retira                           | Low        | Med      | Capa de abstracción `AnthropicClient` con ID de modelo por entorno; prompts compatibles entre Sonnet y Opus; fallback a Haiku documentado.                                                                                                                  |
| R-12 | UI no responsive o no accesible en tablet                              | Med        | Med      | Tailwind con breakpoints desde inicio; dark mode día 1; checks de accesibilidad en review.                                                                                                                                                                  |
| R-13 | Seed data no representativo → bugs encontrados solo en producción      | Med        | Med      | Seed script con datos realistas (cafés, físios, bakeries en Madrid/Barcelona); antes de delivery, ejecución completa de las 6 golden paths con datos sembrados.                                                                                             |
| R-14 | Admin panel queda como afterthought en vez de ciudadano de primera     | Med        | High     | Admin panel tiene su propio milestone (M3 — Admin & Infra); no es "al final".                                                                                                                                                                               |
